# Validation Test Cases

핵심 End-to-End 동작과 예외 처리 흐름을 검증하기 위한 대표 테스트 케이스입니다.

| 번호 | 테스트 내용 | 입력/조건 | 기대 결과 | 합격 기준 |
|---|---|---|---|---|
| TC-01 | 공구 수명 끝까지 마모 진행 및 HOLD | 센서 이상 없이 모니터링을 시작하고 공구 마모가 사용 한계까지 진행 | 정상 → 초기 마모 → 마모 진행 → 교체 임박 → 교체 필요로 상태가 변화하고 최종적으로 공구 교체 요청 | 최종 상태에서 `HOLD`, `CHANGE_TOOL_REQUEST`가 출력되고 Wear Index, Tool Health, 권장조치가 연속 갱신됨 |
| TC-02 | 센서 이상 발생 및 마모 오판 방지 | 진동·음향·절삭력 중 센서 이상 선택 | 센서 이상을 공구 마모와 구분하고 해당 구간의 마모 확정을 보류한 뒤 센서 재점검을 권고 | `SENSOR_FAULT`, 이상 센서 표시, `RECHECK_SENSOR` 출력 및 가공상태 `RUN` 유지 |
| TC-03 | 센서 이상 해제 후 정상 작동 복귀 | 센서 이상 발생 후 모니터링 일시정지 → 센서 이상 해제 → 모니터링 재시작 | 센서 정상화 후 별도 프로그램 재시작 없이 공구 마모 판단이 정상적으로 복귀 | `SENSOR_FAULT` 해제 후 정상 센서값이 다시 반영되고 기존 공구의 누적 마모 상태를 이어서 분석 |
| TC-04 | 공구 교체 후 재검증 및 가공 재개 | 교체 필요 상태에서 공구 교체 수행 | 새 Tool ID가 생성되고 새 공구는 6개 연속 정상 분석 구간을 재검증한 뒤 재가동 가능 상태로 전환 | 새 Tool ID 생성 → 6/6 통과 → `REVALIDATION_PASSED` → 사용자가 `이어서 시작` 후 가공 재개 |
| TC-05 | 검사 이력 및 결과 요약 확인 | 정상 가공, 센서 이상, 공구 교체 등 테스트 수행 후 공구 사용 이력과 전체 이력 확인 | Run별·Tool별 검사 이력, 가공 사이클 수, 마모도, 건강도, 상태, 이벤트 및 결과 요약이 구분되어 저장·조회됨 | 화면의 공구 사용 이력과 전체 이력 CSV/PDF에서 `RUN #1`, `RUN #2` 및 각 Tool ID별 기록이 구분되어 확인됨 |

## TC-01 공구 수명 끝까지 마모 진행 및 HOLD

- 목적: 정상 공구가 사용에 따라 점진적으로 마모되고 최종적으로 교체 필요 상태에서 안전하게 HOLD되는 전체 흐름 검증
- 확인 순서: 모니터링 시작 → 센서 데이터 → 특징 계산 → Wear Index/Tool Health 갱신 → 마모 단계 변화 → 교체 임박 → 교체 필요 → HOLD
- 예상 조치: 정상에서는 `CONTINUE`, 마모 진행 시 `MONITOR` 또는 `PREPARE_CHANGE`, 지속적인 고마모 상태에서는 `HOLD`, `CHANGE_TOOL_REQUEST`
- 핵심 확인: 순간적인 한 번의 값이 아니라 실제 마모 진행 흐름을 따라 최종 교체 요청까지 연결되는지 확인

## TC-02 센서 이상 발생 및 마모 오판 방지

- 목적: 센서 이상을 공구 마모로 오판하지 않는지 검증
- 진동·음향·절삭력 중 센서 이상을 선택하고 예약된 구간 이후 실제 센서 특징값의 비정상 변화를 확인
- Agent는 이상 선택값 자체가 아니라 변화된 센서 특징값을 통해 이상을 감지
- 센서 이상 중에도 가공과 데이터 수집은 계속하고, 신뢰되지 않는 구간의 공구 마모 확정만 보류
- 센서 이상 구간은 공구 사용 이력에는 기록하되, 이후 마모 판단을 위한 학습·보정 데이터에서는 제외

## TC-03 센서 이상 해제 후 정상 작동 복귀

- 목적: 센서 이상 해제 후 기존 공구의 누적 마모 상태를 유지한 채 정상 분석으로 복귀하는지 검증
- 확인 순서: 정상 가공 → 센서 이상 발생 → `SENSOR_FAULT` / `RECHECK_SENSOR` → 모니터링 일시정지 → 센서 이상 해제 → 모니터링 재시작
- 센서가 정상화되면 별도 프로그램 재시작이나 전체 초기화 없이 다음 정상 데이터부터 공구 마모 판단을 다시 수행
- 센서 이상 발생 중에도 공구의 실제 마모 진행은 유지되며, 복구 후 해당 누적 마모 상태를 이어서 분석
- 복구 후 정상 구간 데이터는 다시 공구 마모 판단 및 이력 기반 보정에 사용

## TC-04 공구 교체 후 재검증 및 가공 재개

- 목적: 공구 교체 후 새 공구를 즉시 가동하지 않고 정상성을 재검증한 뒤 안전하게 가공을 재개하는 흐름 검증
- 확인 순서: `HOLD / CHANGE_TOOL_REQUEST` → 공구 교체 → 새 Tool ID 생성 → `REVALIDATION_REQUIRED` → 정상 분석 구간 1/6 ~ 6/6 → `REVALIDATION_PASSED` → `이어서 시작`
- 새 공구는 6개 연속 정상 분석 구간을 모두 통과해야 재가동 가능 상태가 됨
- 재검증 통과 후에도 사용자가 `이어서 시작`을 눌러야 실제 가공이 재개됨
- 기존 공구의 사용 이력은 삭제하지 않고 유지되며 새 공구는 별도 Tool ID로 관리

## TC-05 검사 이력 및 결과 요약 확인

- 목적: 검사 과정에서 생성된 공구 사용 이력과 이벤트 및 최종 결과가 정상적으로 저장·조회·요약되는지 검증
- 확인 항목: Run 번호, Tool ID, 가공 사이클 수, 현재 또는 교체 시 마모도, 공구 건강도, 마지막 상태, 종료 사유, 센서 이상 이벤트, 공구 교체 및 재검증 이벤트
- 세션 초기화 후에도 현재 Run의 기존 이벤트와 공구 사용 이력이 유지되는지 확인
- 전체 초기화 후에는 새 Run이 시작되지만 과거 Run의 공구 사용 이력은 DB에 보존되는지 확인
- `전체 이력 CSV`와 `전체 이력 PDF`에서 `RUN #1`, `RUN #2` 등 Run별로 구분되고 각 Run 내부의 Tool ID별 기록이 확인되는지 검증
- 과거 정상 공구 사용 이력은 이후 공구 마모 판단의 보조 데이터로 활용되고, 센서 이상 구간은 이력에는 남되 학습·보정에서는 제외되는지 확인
